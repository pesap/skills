# README guidance

A README is the project's entry point, not its complete manual. Optimize for a
new reader reaching a verified result quickly, then link to deeper material.

## Recommended order

1. State what the project does, who it serves, and its key constraint.
2. Give a 30–90 second quickstart with exact installation and run commands.
3. Show expected output and a small success check.
4. Explain only the concepts needed for the normal workflow.
5. Link to tutorials, how-to guides, API reference, explanations, and
   troubleshooting.
6. Put advanced configuration, extension points, and limitations after the
   primary path or in linked documents.

Keep badges few and meaningful. Verify setup from a clean or documented
environment, include hidden prerequisites, and make every quickstart command
copy-pasteable. Do not duplicate a full manual in the README.
