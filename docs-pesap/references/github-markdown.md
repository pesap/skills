# GitHub Markdown

Optimize source navigation, rendered readability, and accessibility.

- Keep a logical heading hierarchy; do not skip levels.
- Use descriptive headings, short paragraphs, lists, and numbered procedures.
- Prefer relative repository links and verify every target and anchor.
- Use tables for compact lookup, not long prose.
- Use GitHub callouts only when they add signal: `[!NOTE]`, `[!TIP]`,
  `[!IMPORTANT]`, `[!WARNING]`, or `[!CAUTION]`.
- Put optional depth in `<details>`; never hide required steps there.
- Use Mermaid only for simple diagrams that remain understandable in source.
- Keep badges, emoji, decorative HTML, and screenshots purposeful and
  accessible. Add useful alt text to images.
- Label fenced code blocks with the language and keep commands copy-pasteable.
- When commands and expected output share a shell block, prefix output with `#`
  so pasting the block cannot execute it.

Preview GitHub-specific rendering when the change depends on tables, callouts,
anchors, nested lists, details blocks, or Mermaid.
